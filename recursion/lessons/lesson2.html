Lección 2: Metodología para Analizar Problemas Recursivos

Aprendiendo a pensar de manera recursiva

Nivel Básico-Intermedio 45 minutos estimados

El Arte de Pensar Recursivamente

Pensar recursivamente es una habilidad que se desarrolla con práctica. No es natural al principio, pero con un enfoque sistemático, cualquier problema puede descomponerse.

El Framework de 4 Pasos

Sigue estos pasos cada vez que te enfrentes a un problema recursivo:

  1. Identificar el caso base (¿Cuándo paramos?)
  2. Identificar el caso recursivo (¿Cómo reducimos el problema?)
  3. Verificar que avanza hacia el caso base (¿Cada llamada se acerca al final?)
  4. Probar con ejemplos pequeños (¿Funciona para n=1, n=2?)

Paso 1: Identificar el Caso Base

El caso base es tu punto de detención. Es la condición más simple que puedes resolver SIN recursividad.

Tipos comunes de casos base:

  • Números: n = 0, n = 1, n ≤ 0
  • Strings: longitud = 0 o 1
  • Arrays: longitud = 0 o 1
  • Árboles: nodo es null

Ejemplo: Encontrar el Caso Base

Problema: Calcular la suma de los primeros n números naturales.

Pregunta: ¿Cuál es la situación más simple posible?

Respuesta: Si n = 1, la suma es simplemente 1.

Pregunta: ¿Y si n = 0?

Respuesta: La suma de los primeros 0 números es 0.

✓ Caso base: n ≤ 1 (retornar n)

Paso 2: Identificar el Caso Recursivo

El caso recursivo es donde ocurre la "magia". Aquí divides el problema en versiones más pequeñas del mismo problema.

Técnica: "Un paso a la vez"

Resuelve UNA instancia del problema ahora, y delega el resto a una llamada recursiva.

Suma(n) =

  1. Resuelve n ahora mismo (no es recursivo)
  2. Llama a Suma(n-1) para el resto (sí es recursivo)

Patrones Comunes de Descomposición

Patrón Ejemplo Fórmula
Decrecer de 1 Factorial, suma f(n) = operación + f(n-1)
Partir a la mitad Búsqueda binaria f(n) = f(n/2) + ...
Dividir en N partes Fibonacci f(n) = f(a) + f(b)
Procesar primero/último String reverso f(arr) = [último] + f(resto)

Paso 3: ¿Avanza Hacia el Caso Base?

Un error común es crear una recursión que no se acerca al caso base, causando infinite recursion.

✓ CORRECTO: Se acerca al caso base

function decrecer(n) {
    if (n === 0) return;
    console.log(n);
    decrecer(n - 1); // ← Disminuye n, se acerca a 0
}

✗ INCORRECTO: No se acerca

function error(n) {
    if (n === 0) return;
    console.log(n);
    error(n); // ← Mismo valor, infinito
}

Pregunta de Verificación

Para cada llamada recursiva, pregunta: "¿Este argumento está más cerca del caso base que el anterior?"

Paso 4: Probar con Casos Pequeños

Nunca asumas que tu solución funciona. Pruébala manualmente con valores pequeños.

Proceso de Validación

  1. n = 0: ¿Maneja el caso base correctamente?
  2. n = 1: ¿Funciona la primera llamada recursiva?
  3. n = 2: ¿Dos niveles de recursión funcionan?
  4. n = 3: ¿El patrón es consistente?

Ejemplo Completo: factorial(3)

factorial(3)
  → return 3 * factorial(2)
    → return 2 * factorial(1)
      → return 1  [CASO BASE]
    ← return 2 * 1 = 2
  ← return 3 * 2 = 6
← return 6

Análisis: Cada retorno desenreda la pila. El caso base (factorial(1) = 1) inicia el proceso inverso.

Ejemplo Guiado: Suma de Pares

Vamos a resolver un problema paso a paso usando nuestro framework.

Problema: Sumar todos los números pares desde 1 hasta n

Ejemplo: sumaPares(6) = 2 + 4 + 6 = 12

1

Identificar el Caso Base

Si n < 2, no hay pares, retornar 0.

if (n < 2) return 0;
2

Identificar el Caso Recursivo

¿Es n par? Si sí, agregar n y procesar n-1. Si no, solo procesar n-1.

if (n % 2 === 0) {
    return n + sumaPares(n - 1);
} else {
    return sumaPares(n - 1);
}
3

Verificar Avance

Cada llamada decrece n en 1 → se acerca al caso base (n < 2). ✓

4

Probar Manualmente

sumaPares(4):

  • n=4 (par) → 4 + sumaPares(3)
  • n=3 (impar) → sumaPares(2)
  • n=2 (par) → 2 + sumaPares(1)
  • n=1 (<2) → 0 [BASE]
  • Desenrollar: 2+0=2, luego 4+2=6 ✓

Código Final

function sumaPares(n) {
    // Caso base
    if (n < 2) {
        return 0;
    }
    
    // n es par?
    if (n % 2 === 0) {
        return n + sumaPares(n - 1);
    } else {
        return sumaPares(n - 1);
    }
}

// Versión más concisa
function sumaPares2(n) {
    if (n < 2) return 0;
    return (n % 2 === 0 ? n : 0) + sumaPares2(n - 1);
}

// Pruebas
console.log(sumaPares(6));  // 12 (2+4+6)
console.log(sumaPares(10)); // 30 (2+4+6+8+10)

Errores Comunes y Cómo Evitarlos

⚠️

Falta de Caso Base

Síntoma: Stack overflow error. Solución: Siempre define el caso base PRIMERO.

⚠️

No Acercarse al Caso Base

Síntoma: Recursión infinita. Solución: Verifica que cada llamada modifique los parámetros.

⚠️

Múltiples Llamadas Ineficientes

Síntoma: Muy lento para n grande. Solución: Usa memoización (lección futura).

⚠️

Off-by-One Errors

Síntoma: Resultados incorrectos por 1. Solución: Traza manualmente con valores pequeños.

Checklist de Debugging

  • ¿El caso base retorna el valor correcto?
  • ¿La llamada recursiva usa argumentos modificados?
  • ¿El resultado de la llamada recursiva se usa correctamente?
  • ¿Hay return en el caso recursivo?
  • ¿El control fluye correctamente (no se ejecutan ambos casos)?

Ejercicio de Análisis: Strings Palíndromos

Vamos a analizar este problema paso a paso.

Problema

Determinar si un string es un palíndromo (se lee igual al derecho y al revés).

Ejemplos: "ana" → true, "hola" → false

Preguntas de Análisis

  1. ¿Cuál es la versión más simple del problema?
  2. ¿Cómo comparar primer y último carácter?
  3. ¿Qué hacemos con el resto del string?

Respuestas

  1. String vacío o de 1 carácter → siempre es palíndromo
  2. Comparar str[0] con str[str.length-1]
  3. Llamada recursiva con str.slice(1, -1)
function esPalindrome(str) {
    // Caso base: 0 o 1 carácter
    if (str.length <= 1) {
        return true;
    }
    
    // Comparar extremos
    if (str[0] !== str[str.length - 1]) {
        return false;
    }
    
    // Caso recursivo: verificar substring interno
    return esPalindrome(str.slice(1, -1));
}

Aprendizajes Clave de Esta Lección

  • Usa el framework de 4 pasos para cualquier problema recursivo.
  • El caso base es la condición más simple que resuelves SIN recursión.
  • El caso recursivo debe disminuir el problema hacia el caso base.
  • Siempre prueba manualmente con casos pequeños antes de codificar.
  • Piensa en "un paso a la vez": resuelve una parte y delega el resto.
