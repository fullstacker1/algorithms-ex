Lección 6: Backtracking

La técnica de exploración y retroceso

Nivel Avanzado 50 minutos estimados

¿Qué es Backtracking?

Backtracking ("volver atrás") es una técnica recursiva que explora sistemáticamente todas las posibles soluciones de un problema, "retrocediendo" cuando un camino no conduce a una solución válida.

Analogía: Laberinto

Imagina que estás en un laberinto. En cada cruce, eliges un camino. Si llegas a un callejón sin salida, regresas (backtrack) al último cruce y pruebas otra ruta. Sigues hasta encontrar la salida o agotar todas las opciones.

Backtracking vs Recursión Simple

Recursión Simple

  • Una sola llamada recursiva
  • Divide el problema en UN subproblema
  • Ejemplo: factorial(n) = n × factorial(n-1)
  • Camino único

Backtracking

  • Múltiples llamadas recursivas por nivel
  • Explora MÚLTIPLES opciones en cada paso
  • Ejemplo: subsets → incluir o no incluir
  • Árbol de decisiones

La Plantilla Universal

Estructura Básica

function backtrack(solucionParcial, decisiones) {
    // 1. CASO BASE: ¿Llegamos a una solución completa?
    if (esSolucionCompleta(solucionParcial)) {
        guardarSolucion(solucionParcial);
        return;
    }
    
    // 2. OPCIONES: Iterar sobre todas las posibles decisiones
    for (cada opcion in opcionesDisponibles) {
        // 3. ELEGIR: Aplicar la opción
        aplicarOpcion(opcion);
        
        // 4. EXPLORAR: Recursión
        backtrack(solucionParcial, decisiones);
        
        // 5. DESHACER (Backtrack): Eliminar la opción
        deshacerOpcion(opcion);
    }
}

Los 5 Pasos del Backtracking

1

Identificar Estado

¿Qué información necesitas llevar en cada llamada? (array actual, posición, etc.)

2

Definir Caso Base

¿Cuándo una solución está completa y es válida? (longitud alcanzada, suma exacta, etc.)

3

Generar Opciones

¿Qué decisiones puedes tomar en este punto? (incluir/no incluir, elegir elemento, dirección)

4

Explorar

Para cada opción: aplicarla, llamar recursivamente, deshacerla.

5

Podar (Opcional)

¿Hay condiciones que inmediatamente descarten una rama? (límite superado, inválido)

Ejemplo 1: Generar Subsets

El power set: todos los subconjuntos posibles de un conjunto.

Análisis del Problema

Estado:

  • índice actual
  • subconjunto actual
  • resultado acumulado

Casos base:

índice == longitud → guardar subset

Opciones por elemento:

1. Incluir elemento

2. No incluir elemento

Complejidad:

O(2^n) subsets posibles

JavaScript 
function subsets(arr, idx, actual, resultado) {
    // Caso base: fin del array
    if (idx === arr.length) {
        resultado.push([...actual]);
        return;
    }
    
    // Opción 1: NO incluir arr[idx]
    subsets(arr, idx + 1, actual, resultado);
    
    // Opción 2: SÍ incluir arr[idx]
    actual.push(arr[idx]);
    subsets(arr, idx + 1, actual, resultado);
    actual.pop(); // ← BACKTRACK: deshacer elección
}

function generarSubsets(arr) {
    const resultado = [];
    subsets(arr, 0, [], resultado);
    return resultado;
}

// Visualización para [1,2]
//                    []
//                   /   \
//              [1]       []          (decisión: incluir 1 o no)
//             /   \    /   \
//        [1,2]  [1]  [2]   []       (decisión: incluir 2 o no)
//

Árbol de Decisión

                     []
                    /           \
                 [1]            []
                /     \        /     \
            [1,2]    [1]    [2]    []
           (aceptar) (no)  (acept.) (no)

Cada nodo es una llamada recursiva. Las hojas son subsets completos.

Ejemplo 2: Permutaciones

Generar todos los ordenamientos posibles de N elementos.

Enfoque con Swap

Para permutar, intercambiamos cada elemento con cada posición desde el índice actual.

JavaScript 
function permutaciones(arr, idx, resultado) {
    // Caso base
    if (idx === arr.length) {
        resultado.push([...arr]);
        return;
    }
    
    for (let i = idx; i < arr.length; i++) {
        // ELEGIR: intercambiar arr[idx] con arr[i]
        [arr[idx], arr[i]] = [arr[i], arr[idx]];
        
        // EXPLORAR: recursión con siguiente posición
        permutaciones(arr, idx + 1, resultado);
        
        // DESHACER (backtrack): volver al estado original
        [arr[idx], arr[i]] = [arr[i], arr[idx]];
    }
}

function getPermutaciones(arr) {
    const resultado = [];
    permutaciones(arr, 0, resultado);
    return resultado;
}

// Para [1,2,3]:
// idx=0: i=0→[1], i=1→[2], i=2→[3] (3 ramas)
// Cada rama genera 2! = 2 permutaciones más
// Total: 3 × 2 = 6 permutaciones

Ejemplo 3: Paréntesis Válidos

Generar todas las combinaciones de N pares de paréntesis bien formados.

Condiciones de Validez

  • No puedes cerrar un paréntesis que no abriste
  • En cualquier punto: #abiertos ≥ #cerrados
  • Al final: #abiertos = #cerrados = N
JavaScript 
function generarParentesis(n, abiertos, cerrados, actual, resultado) {
    // Caso base: string completo
    if (actual.length === n * 2) {
        resultado.push(actual);
        return;
    }
    
    // Puedo abrir si aún no llegué al límite
    if (abiertos < n) {
        generarParentesis(n, abiertos + 1, cerrados, actual + '(', resultado);
    }
    
    // Puedo cerrar solo si hay más abiertos que cerrados
    if (cerrados < abiertos) {
        generarParentesis(n, abiertos, cerrados + 1, actual + ')', resultado);
    }
}

function parentesisValidos(n) {
    const resultado = [];
    generarParentesis(n, 0, 0, '', resultado);
    return resultado;
}

//                      ""
//                    /      \
//                 "("        ""
//               /    \       \
//            "(("    "()"     "" (no puede cerrar porque abiertos=0)
//            /  \      \
//         "(((" "(()"  ... → al final达成"()" y "(())"

Poda de Ramas (Pruning)

Optimización: no explorar ramas que sabemos no llevan a solución.

Subset Sum

Si la suma parcial ya supera el target, no sigas.

if (sumaActual > target) return;

N-Reinas

Si una reina amenaza a otra, no continúes esa rama.

if (hayConflicto()) return;

Combinación Sum

Ordena candidatos y evita duplicados.

if (i > 0 && arr[i] === arr[i-1] && !usado[i-1]) continue;

Complexidad en Backtracking

El backtracking puede ser costoso, pero a menudo es la única solución exacta.

Problema Complejidad Peor Caso Espacio
Subsets O(2^n × n) - 2^n subsets, cada uno length n O(n)
Permutaciones O(n! × n) O(n)
Combinaciones C(n,k) O(C(n,k) × k) O(k)
N-Reinas O(n!) aproximadamente O(n)

Errores Comunes

Olvidar el Backtrack (pop/remove)

Síntoma: todos los resultados son iguales o incompletos. Solución: SIEMPRE deshace la acción después de la recursión.

No validar estado antes de profundizar

Síntoma: exploras caminos inválidos innecesariamente. Solución: verifica condiciones ANTES de llamar recursión.

Copiar arrays incorrectamente

Síntoma: las soluciones se modifican después de guardarlas. Solución: usa spread operator [...arr] al guardar.

Condiciones de terminación confusas

Síntoma: recursión infinita o resultados perdidos. Solución: traza el árbol de decisiones en papel.

Aprendizajes Clave de Esta Lección

  • Backtracking explora múltiples caminos en árbol de decisiones.
  • Siempre sigue el ciclo: Elegir → Explorar → Deshacer.
  • El estado (parámetros) debe capturar toda la información necesaria.
  • El caso base reconoce soluciones completas y válidas.
  • La poda (pruning) mejora significativamente el rendimiento.
  • Común en: subsets, permutaciones, combinaciones, problemas de restricción.
